  2026-09-11 晚修正（实机测试后）：
    - 打开 CONFIG_LIBC_FLOATINGPOINT：此前串口打印 %f 会显示成 "*float*"，
      现在电流零点、电流、温度都能正常打印小数；
    - 固件里的日志全部改成英文（原中文日志在按 GBK 解析的串口工具里是乱码），
      OLED 也只显示 ASCII。
    - 周期数据打印从 DEBUG 级提到 INFO 级：启动后每 10 秒在串口打印一行
      "FireEye: I=x.xx A, T=xx.x C, state=..."，方便直接看数值。
    - 修了 OLED 不亮的 bug：旧驱动命令缓冲区只有 16 字节却按 24 字节发送，
      既越界又把初始化命令截断，导致收尾的电荷泵命令 0x8D 0x14 从未发出
      （SSD1306 没开电荷泵，屏幕永远全黑）。现改成分批发送、命令表补全，
      初始化失败时还会自动重试 0x3D 地址，并且串口会明确提示成功/失败。
    - 串口 nsh 里新增 i2c 工具，可直接扫描 I2C1 上有没有 OLED。
    - 又修了一个 I2C bug：I2C 报文的 frequency 字段原来没赋值（栈上随机值），
      而 GD32 的 I2C 驱动用它计算 SCK 分频，导致时钟是乱的、器件不应答。
      现在显式设为 100kHz。
    - 修正 OLED 失败日志：之前打印的是别的变量（显示成 0），现在打印真实错误码。
    - 去掉"采样失败就偷偷用模拟数据"的行为：以前温度读不到时会显示模拟温度，
      还会模拟出漏电（L=1）把状态机推到 ALARM，很容易被误读成"测得不准/误报警"。
      现在真实模式下采样失败就标记为无效（OLED 显示 --、串口限频提示），
      漏电通道恒为 false（本板没有漏电互感器）；同时温度超出 -40~150℃ 直接判无效。
    - 新增硬件自检子命令：nsh 里执行 `fireeye test`，
      会依次测试 蜂鸣器（PB1/JP5-16）与 继电器（PB0/JP5-13）：
        3 短声 → 继电器吸合 2 秒再释放 → 1Hz 预警音型 3 秒 → 结束
      这条路径和真实报警走的是同一套输出代码，测通即说明报警链路正常。
    - 新增报警灯模块支持（3 脚模块，5V 供电 + 信号脚）：
      信号脚 → JP5 第 31 脚（PD9）；预警时 1Hz 慢闪，报警时常亮，正常熄灭。
      `fireeye test` 里也加了"亮 1 秒/灭 1 秒 ×3"的灯测试。
      若模块是低电平触发（灯常亮不灭），把板级宏 `FIREEYE_LED_ACTIVE_HIGH` 改成 0 重新编译即可。
    - 输出极性（2026-09-13 首测，继电器于 2026-09-18 重新定标）：
      * 继电器：**高电平触发**（`FIREEYE_RELAY_ACTIVE_LOW = 0`，2026-09-18 重新定标）；
        依据：负载接 COM+NC、未运行 fireeye 时——IN 悬空 = 释放 = 风扇转；IN 接 PB0
        （此刻被板级 bring-up 驱动为 HIGH）= 吸合 = 风扇停。IN 悬空不可能导通光耦，
        所以 HIGH 才是有效电平。（09-13 那条低电平触发是拿负电流读数反推的，属循环论证。）
      * 报警灯：高电平触发（`FIREEYE_LED_ACTIVE_HIGH = 1`），`fireeye level` 实测 HIGH 时点亮；
      * 蜂鸣器：**低电平触发**（`FIREEYE_BUZZER_ACTIVE_HIGH = 0`）；实机加热验证：
        50℃ 间歇报警、60℃ 长鸣并报警，行为正常。
    - 零点校准：开机先让继电器吸合（断开负载）0.5 秒再采样零点，然后恢复负载；
      避免把负载电流当成零点（此前出现的 -0.16A 就是这个问题）。极性定对之后，
      这一步才是真的先断开负载再校准。
    - 上电默认（2026-09-18 起）：板级 bring-up 就把继电器吸合、负载断电；只有 fireeye
      跑起来进入 NORMAL 才恢复供电——上电不转、运行才转，等于未监测就不给充电回路通电。
    - 当前实测 NORMAL 状态表现：风扇转、灯灭、蜂鸣器静音、串口 state=NORMAL ✔
    - 新增 `fireeye level` 命令：三个输出脚（蜂鸣器 PB1 / 继电器 PB0 / 报警灯 PD9）
      依次输出 LOW 2 秒、HIGH 2 秒，用来确认每个模块的触发极性；
      若某个模块动作相反，改对应的板级宏重新编译即可。

二、这一版新做了什么（P1 范围）

  1. ADC 采样：openvela 里没有 GD32F4 的 ADC 驱动，按官方用户手册
     （GD32F4xx User Manual Rev3.4 第 14 章）自己写了一个板级模块：
     ADC0、12 位、ADCCK=PCLK2/4(21MHz)、480 周期采样时间、前台校准。
  2. 电流换算：ACS712-30A（66mV/A），输出经 10k+10k 分压后进 PA4；
     上电时自动做一次零点校准。
  3. 温度换算：10kΩ + NTC(10K B3950) 分压，中点进 PA6，用 B 参数方程换算。
  4. 报警输出：蜂鸣器（预警间歇 1Hz / 报警长鸣）+ 继电器联动断电。
  5. 人工复位：按板载按键 K2，状态机回到 NORMAL，同时关掉报警、继电器复位。
  6. OLED（SSD1306，I2C1）：显示状态 / 电流 / 温度，每秒刷新。
  7. 板级 LED 自检保留：上电 2 次快闪 + 5 次快闪 + 1Hz 心跳。

  | 信号            | 开发板脚 | 排针位置 | 接到哪里                        |

  | 继电器 IN       | PB0     | JP5-13  | 继电器模块 IN                   |
  | 蜂鸣器 +        | PB1     | JP5-16  | 蜂鸣器正极（裸蜂鸣器建议加三极管）|
  | OLED SDA        | PB11    | JP5-25  | OLED SDA                        |
  | OLED SCL        | PB10    | JP5-26  | OLED SCL                        |

  两个分压电路必须自己搭（不能省）：

    温度：3V3 ──[10kΩ]──●──[NTC 10K B3950]── GND        ● → PA6 (JP5-9)
    电流：ACS712 OUT ──[10kΩ]──●──[10kΩ]── GND           ● → PA4 (JP5-7)

  电源（用你的电源模块）：
    - 5V   → ACS712 VCC、继电器模块 VCC（继电器线圈约 70mA）
    - 3V3  → 用开发板 JP6-2 取电（NTC 分压、OLED、W25Q64）
    - 电源模块 GND 必须和开发板 GND 连一起
    - 开发板自己仍然用 USB 供电，不要把电源模块的 3.3V 灌到开发板


四、上电后应该看到

  1. 板载 LED2（PC6）：快闪 2 次 → 快闪 5 次 → 1Hz 心跳（程序在跑）
  2. 串口（115200-8-N-1）：
         NuttShell (NSH)
         nsh>
     输入 fireeye 启动火眼应用，Ctrl-C 退出
  3. 火眼应用启动时会打印「电流零点 = x.xxxV」，之后每 10 秒打印一次数据
  4. OLED：第 1 行 FireEye，第 2 行状态（NORMAL/WARNING/ALARM/SHUTDOWN），
     第 3 行 I=xx.xxA，第 4 行 T=xx.xxC
  5. 按住 K2：LED 与蜂鸣器复位，状态机回到 NORMAL


五、调试要点（重要）

  0. OLED 排查（这一版刚修完，先看这个）
     - 烧录后启动日志应出现 "FireEye: OLED init OK"；
       若是 "FireEye: OLED init FAILED"，说明 I2C1 上没有器件应答。
       （错误码含义：-19 = /dev/i2c1 设备节点不存在；-5 = 器件不应答，查接线/地址）
     - 启动时还会打印两路 ADC 的原始值与电压（PA4/PA6），方便用万用表对照。
     - nsh 里可直接扫描：`i2c bus`（列出总线，应看到 Bus 1 → /dev/i2c1）
       → `i2c bus 1` → `i2c dev 0x03 0x77`；有回应的就是屏的地址
       （0x3c、0x3d 都常见）。
     - 扫不到就查线：SDA→JP5 第 25 脚(PB11)、SCL→JP5 第 26 脚(PB10)、
       VCC→JP6 第 2 脚(3V3)、GND→JP6 第 1 脚。**SDA/SCL 接反是最常见原因**。
     - 如果你的 OLED 是 7 针的 SPI 版（不是 4 针 I2C 版），告诉我，需要换驱动。

  1. ACS712 是 5V 供电、输出 0.5~4.5V，**分压电阻必须接**，
     直接把 5V 输出接 PA4 会打坏引脚。
  2. 上电校准零点时电流回路应是断开的（串口会打印零点电压，
     正常约 1.16~1.25V（ACS712 输出 = Vcc/2，2026-09-18 实测 1.161V，对应该 5V 实际约 4.64V）；明显偏离就检查分压电阻和 5V 供电）。
  3. 传感器没接时读数无意义（温度可能显示异常值），先接好再判断。
  4. 继电器按**高电平触发**处理（`FIREEYE_RELAY_ACTIVE_LOW=0`）；换模块后若动作相反，改这一个宏重新编译即可。IN 悬空=释放=负载通电，线一定要插牢。
  5. 蜂鸣器若是裸的两脚（不是模块），建议用 NPN 三极管 + 1kΩ 基极电阻驱动。
  6. OLED 如果没插，/dev/i2c1 的写会失败，不影响其他功能（串口会提示一次）。
