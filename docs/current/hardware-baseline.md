# 新载板硬件基线

> 事实来源：用户 2026-10-23 确认 PCB 已完成焊接；电气参数来自载板设计文档和
> TI INA228 数据手册；2026-10-25 使用独立 STM32F103 硬件 I2C2 验证器件和总线；
> 2026-10-28 根据 PCB 铜箔图和实机现象更新继电器与 W5500 状态。未标记
> “已实测”的项目仍需上板验证。

产品范围与升级路线见 [scope-and-roadmap.md](scope-and-roadmap.md)。当前硬件
是24V低压原型，不覆盖主流48V/60V/72V充电器的电压和电流范围。

## 一、电源

- 被测回路：24V 输入，经保护、2mΩ 分流和常开继电器后接负载。
- 终端供电：独立 12V 电池，经 MP1584 转 5V、AMS1117 转 3.3V。
- 24V 被测回路不再给终端自取电。
- 12V 电池与 USB 不得同时接入；两路 3.3V 可能对顶。

## 二、电流测量

- 器件：INA228AIDGSR。
- 总线：I2C1，地址 `0x40`。
- 分流电阻：`2mΩ`。
- 配置：`ADCRANGE=1`，量程约 `±40.96mV`，即约 `±20.48A`。
- VSHUNT 分辨率：`78.125nV/LSB`。
- 电流换算：`I = VSHUNT / 0.002Ω`。
- 电流理论分辨率约 `39.0625µA/LSB`，不代表实际精度。
- 固件直接读取 VSHUNT 原始寄存器，不依赖 CURRENT/SHUNT_CAL。

## 三、继电器与负载

- 目标触点接法：`COM → NO → LOAD`；当前 PCB 把 `24V_SW` 接到 NC 3脚，
  而真正的 COM 5脚悬空。最简修法是在 3/5 脚之间加一根短接线。
- 驱动：PB0 高电平使线圈励磁，NO 闭合，负载接通。
- PB0 低电平或掉电时线圈释放，NO 断开，负载断电。
- 应用层只使用“接通负载/断开负载”语义，禁止再用“继电器 true 等于断电”。
- 上电目标和验收要求：未运行应用时负载断开，不应出现非预期负载脉冲。

## 五、独立 I2C 验证

2026-10-25 使用 STM32F103C8T6 硬件 I2C2、PB10/PB11、100 kHz 同时连接
OLED 和 INA228，实测：

- OLED 地址 `0x3C` ACK。
- INA228 地址 `0x40` ACK。
- INA228 `MANUFACTURER_ID=0x5449`、`DEVICE_ID=0x2281`。

详细接线、日志和验证边界见
[i2c-validation-20261025.md](i2c-validation-20261025.md)。

该结果证明器件和共享总线正常，不证明 GD32 的 I2C1 路径已经通过。

2026-10-25 后续完成 GD32 上板分层验证：PB10/PB11 软件位翻转和寄存器级
I2C1 探测均得到 `0x3C`、`0x40` ACK，确认硬件路径正常。故障定位为
NuttX GD32 硬件 I2C 多字节接收状态机；当前应用已改为软件 I2C 访问。
实测 INA228 `mfg=0x5449`、`id=0x2281`，OLED 自检通过。

## 六、继电器实物确认

根据实物确认和同一型号旧板接线，继电器实际功能与当前载板网络如下：

| 继电器引脚 | 实际功能 | 当前载板连接 | 结论 |
|---|---|---|---|
| 1 | 线圈正端 | 5V | 正确 |
| 2 | NO | `LOAD_P`，至 J2-1 | 正确 |
| 3 | NC | `24V_SW` | 与5脚短接后可用 |
| 4 | 线圈负端 | `RELAY_COIL_N` | 正确 |
| 5 | COM | 悬空 | **必须与3脚短接** |

当前新板把 NC 3脚接到 `24V_SW`，却让 COM 5脚悬空。NORMAL 时线圈 1/4脚正常
励磁、2脚切到COM，但COM没有接入被测电源，所以 `LOAD_P` 仍无电压。

返修目标：

1. 用一根足够承载负载电流的绝缘线，把继电器 3脚与5脚直接连接；
2. 3脚已有 `24V_SW`，因此连接后5脚COM也接到 `24V_SW`；
3. 保持 1脚接5V、2脚接 `LOAD_P`、4脚接 `RELAY_COIL_N`；
4. 保持续流二极管阴极在5V、阳极在 `RELAY_COIL_N`。

返修完成后，NORMAL 时线圈 1/4脚励磁，COM 5脚经 NO 2脚接到 `LOAD_P`，
负载通电；ALARM 或掉电时线圈释放，NO 2脚断开，负载断电。NC内部触点虽然被
3/5脚外部短接线旁路，但它不决定负载是否通电，失效安全仍然由NO触点保证。

2026-10-28 已完成3/5脚临时短接并实测通过：

```text
I=0.08 A, T=22.1 C, Vbus=0.8 V, state=NORMAL
```

这证明当前返修后的功率路径工作正常；后续可以继续验证报警断载和掉电断载。

### 返修方式 A（推荐，一根线）

1. 断电；
2. 用一根绝缘线直接连接继电器3脚与5脚；
3. 继电器所有引脚保持原位，不需要切走线或抬脚；
4. 用万用表确认3/5脚确实导通，且短接线没有碰到1、2、4脚。

该方案只需一根飞线。负载电流会经过这根线，建议使用不小于0.2mm²的短线；
验证后使用热熔胶固定，且不得压到24V尖峰或线圈续流节点。

### 返修方式 B（PCB 上短接）

如果5脚焊盘可直接焊接，也可在PCB上从3脚焊盘/`24V_SW`节点补一根短铜线到
5脚焊盘。效果与方式A相同，更适合装壳后的永久连接。

EasyEDA 工程源文件中，两个螺丝端子的实际网络为：

| 端子 | 引脚 1 | 引脚 2 |
|---|---|---|
| U7（电源输入，丝印 JP1） | `24V_IN` | `GND` |
| U8（负载输出，丝印 JP2） | `LOAD_P` | `GND` |

两个端子的 GND 在板上连通，因此 `JP1` 接被测电源、`JP2` 接负载时不需要再额外拉
一根负载回线。只插 USB 调试时，3.3V 可能由主控板反灌，但 12V 电池没有接时
MP1584 不产生 5V，继电器线圈不会吸合；此时软件显示 `state=NORMAL` 也不代表
COM-NO 已经闭合。

## 七、W5500 链路状态

新模块可以完成 SPI 访问和 MACRAW 初始化：

```text
VERR=0x04
SN_SR=0x42
PHYCFGR=0xB8
```

其中 `PHYCFGR` 的 Link 位为 0。同一根网线连接电脑与树莓派时网口灯正常，
连接 W5500 与树莓派时两侧都不亮；电脑网卡持续 `Disconnected`，RX=0。
当前优先怀疑模块 RJ45/PHY/网络变压器链路故障，但尚未通过替换模块或示波器
测量最终确认。用户暂时没有备用模块，因此网络调试冻结。

## 九、载流能力评估（2026-10-29）

INA228的量程与PCB载流能力必须分开评估。2mΩ分流对应约±20.48A的芯片量程，
但当前载板功率路径不能安全承受该电流。

EasyEDA工程源文件中有一条`24V_SW=10mil`的线段，但它位于分流电阻到
INA228 VBUS输入附近，属于高阻采样支路，只承担微安级输入电流，不承担负载
电流，因此10mil在这里合理。

2026-10-29使用EasyEDA实时接口复核当前打开工程`火眼载板1/PCB1`：

| 网络 | 走线统计 |
|---|---|
| `24V_IN` | 6段，全部60mil |
| `24V_SW` | 11段60mil主功率线，另有7段10mil采样线 |
| `LOAD_P` | 4段，全部60mil |

`24V_SW`主功率线跨顶层和底层，使用6个12/24mil过孔连接。10mil线段从分流
电阻附近连接到INA228 VBUS输入，属于高阻采样支路，不承载负载电流。此前把
同名网络的采样支路误判为整条功率链，相关“主功率线只有10mil”的结论撤回。

当前工程功率主回路符合原布线规则要求的`1.5mm（60mil）`。载流限制主要来自
F1和D1，仍需通过实测温升确认连续能力。

主要功率器件评估：

- F1为`1812L200/36GR`，2A保持、36V自恢复保险丝；高环温下保持电流会下降，
  接近2A时还可能因温升和浪涌进入保护。
- D1为SS54，额定约5A/40V；2A时正向压降和功耗已经明显，不适合5A/8A连续电流。
- 继电器触点标称可达15A，不是整板当前的主要瓶颈。
- 2mΩ/3W分流电阻在20A时仅耗散0.8W，不是瓶颈。
- KF128端子本身不是主要瓶颈，但导线、压接和端子温升仍需验证。

### 建议边界

- 0.5–1.0A：可做常规连续带载验证；
- 1.2–1.5A：可较长时间测试，但应持续监测保险丝、二极管、端子和PCB温度；
- 2A：已接近保险丝保持点，不建议连续运行；
- 5A/8A：当前硬件禁止实流测试，必须升级保险丝、二极管、铜宽、端子和线束。

如果只需要验证5A/8A告警逻辑，应把Kconfig阈值临时降到安全范围，例如
`WARNING=0.8A`、`ALARM=1.5A`，使用对应负载验证，而不是把实际电流拉到5A/8A。
