# 固件/硬件代码审查记录（2026-10-29）

> 范围：`app/fireeye/src/*.c`、`patches/vendor-gigadevice-gd32f407v-start.patch`
> 性质：只读审查，未改动代码。每条按严重度排列，给后续修复排优先级。
> 结论口径与 `docs/current/firmware-status.md` 一致——未修复项如实记录。

## 一、高优先级（安全相关）

### H-1 间歇性传感器故障可能绕过失效保护

**位置**：`fireeye_main.c` 主循环 `sensor_invalid_tick` 计数

**现象**：判定逻辑是"连续 N 次失效才告警"，任一次有效读数即把计数清零。
若传感器间歇性故障（隔一次成功一次失败），计数永远到不了 `DEBOUNCE_COUNT`，
系统不会进入 ALARM，但实际数据已不可信。

**影响**：对保护类设备，"间歇失效"正是最危险的一类——测量时好时坏，
阈值判定在真假数据之间摇摆，可能漏掉真实过流。

**建议**：改用滑动窗口（最近 M 次中失效占比 ≥ 阈值）或"累计失效次数不清零、
只在连续 M 次有效后衰减"，避免单次成功就重置。

### H-2 INA228 通信失败后无自动恢复

**位置**：`fireeye_ina228.c`（`g_ina_ready` 只在 init 时置位）

**现象**：初始化成功后 `g_ina_ready` 永久为 true。运行中 I2C 读失败只返回错误，
主循环标记 `g_current_valid=false`，但**驱动不会重新初始化**，必须重启才能恢复。

**影响**：总线受扰动（继电器线圈干扰、接触抖动）后单次 I2C 失败，
整机一直到重启前电流都无效 → 常驻 ALARM，产品不可用。

**建议**：连续 N 次读失败后清 `g_ina_ready` 并自动重跑 `fireeye_ina228_init()`；
恢复成功则退出 ALARM。这是现场可自愈能力。

## 二、中优先级（可靠性）

### M-1 网络发送无超时，可能阻塞上报线程

**位置**：`fireeye_net.c`（`socket/connect/send` 无 `SO_SNDTIMEO`/`SO_RCVTIMEO`）

**现象**：DNS/对端无响应时 `connect()` 可长时间阻塞；`send()` 同理。

**影响**：上报线程挂起，报警事件排队积压；极端情况下拖慢上位机侧链路。

**建议**：设置 `SO_SNDTIMEO`/`SO_RCVTIMEO`（如 5s），或用 `select()` + 非阻塞 connect。

### M-2 `check_leakage_sensor()` 缺少实现说明

**位置**：`fireeye_main.c:211`

**现象**：漏电检测函数存在且参与 `sensors_invalid` 判定，但新载板文档中标注
"漏电监测未实现"。当前返回值与阈值联动来源不清晰。

**影响**：材料与代码口径不一致；若误返回 true 会直接触发 ALARM。

**建议**：明确该函数在新载板上是恒 false 还是预留接口，注释写清，避免误解。

### M-3 INA228 电流/电压两次独立 I2C 读非原子

**位置**：`fireeye_ina228.c` `fireeye_ina228_read_measurement()`

**现象**：先读 VSHUNT 再读 VBUS，两次独立事务；两次之间转换可能更新。

**影响**：电流与母线电压相差一个转换周期，交叉校验时有细微时间差。
本设计直读 VSHUNT 原始码，误差可忽略，仅记录不建议改。

## 三、低优先级（整洁性）

### L-1 `g_ina_fd` 是死资源

**位置**：`fireeye_ina228.c`（`open("/dev/i2c1")` 但读写走位翻转 `gd32_fireeye_i2c_*`）

**现象**：fd 被打开保存，但所有寄存器读写都用板级位翻转接口，fd 从未用于 I/O，
成功路径也从不 close。

**影响**：浪费一个文件描述符，无功能问题。

**建议**：删掉 open/close，或改为真用 NuttX I2C 驱动读写（需先修 GD32 硬件 I2C 收状态机）。

### L-2 `fireeye_sensors_init()` 每个子命令重复初始化板级硬件

**位置**：`fireeye_main.c` 各子命令路径

**现象**：`fireeye current/temp/test/level/adc` 每次都跑完整 `gd32_fireeye_hw_initialize()`
（GPIO/ADC/定时器全配置）。

**影响**：启动慢一点，无功能问题；但诊断命令每次重配 GPIO，若并行有别的外设使用需注意。

### L-3 `filter_moving_average` 的 `index` 无回绕

**位置**：`fireeye_filter.c:68`

**现象**：`ctx->index++` 无限递增，靠取模写环形缓冲。10Hz 下约 6.8 年溢出 int32。

**影响**：实际无影响，仅记录。

## 四、已验证无问题的点

- **继电器默认安全**：`gd32_fireeye_hw_initialize()` 里 `set_relay(false)` → 上电负载断开 ✅
- **极性语义**：`FIREEYE_RELAY_ACTIVE_LOW=0`，PB0 高=励磁=接通，与 NO 触点一致 ✅
- **20 位有符号扩展**：`ina_signed_20bit()` 符号位处理正确 ✅
- **VSHUNT 换算**：`raw * 78.125nV / 2mΩ`，与 ADCRANGE=1 配置一致 ✅
- **NTC 开路/短路判定**：电压贴近 0 或 VREF 判无效，配合 -40~150°C 合理性检查 ✅
- **阈值趋势**：只用正斜率 + 窗口累计升幅双条件，抑制噪声误报 ✅
- **滤波首样本**：低通直接初始化，避免暖机假升温趋势 ✅
