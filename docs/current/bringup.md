# 新载板上板验收顺序

首次上电不要直接运行旧演示流程。按以下顺序逐项记录结果。

GD32 上板后已确认 PB10/PB11、AF4、INA228 和 OLED 硬件路径正常。
NuttX GD32 硬件 I2C 多字节接收状态机存在缺陷，当前应用使用软件 I2C
完成 INA228/OLED 访问。详见
[i2c-validation-20261025.md](i2c-validation-20261025.md)。

## 1. 静态检查

- 万用表检查 12V 输入、5V、3.3V 对地是否短路。
- 检查 INA228、OLED、W5500 供电脚和地。
- 检查 2mΩ 分流电阻、继电器 COM/NO、负载端子接线。
- 确认 12V 电池和 USB 不同时接入。

## 2. 空载上电

- 不接负载，只给 12V 电池。
- 观察是否只有预期的一次继电器动作；记录是否出现连续抖动或负载导通脉冲。
- 蜂鸣器应保持关闭。
- 测量 12V、5V、3.3V。

## 3. 总线与传感器

```text
nsh> i2c bus
nsh> i2c dev -b1 -f100000 0x3c 0x40
nsh> fireeye current
nsh> fireeye oled
```

期望：

- INA228 总线地址 `0x40`。
- 厂商 ID `0x5449`。
- 设备 ID 的高 12 位为 `0x228`，最低 4 位是版本号。
- 空载电流接近 0，母线电压应为实际被测电压量级。
- NTC 原始码不应持续为 `0` 或 `4095`；`4095` 通常表示 PA6 分压中点接近
  3.3V，应先检查 NTC 开路、插接和分压焊点。

2026-10-25 空载实测为 `mfg=0x5449`、`id=0x2281`、`raw20=2`、
`current=0.000 A`、`bus=0.01 V`。2026-10-27 NTC 常温约 24–32℃，
`65.5℃` 进入 ALARM，降至 `44.8℃` 恢复 NORMAL。

## 4. 输出与负载

```text
nsh> fireeye test
nsh> fireeye level
```

逐项确认蜂鸣器、报警灯和继电器动作。继电器必须按“接通负载/断开负载”记录，不只记录 GPIO 高低。

目标接法是 `COM -> NO -> LOAD`，正常构建不要启用
`CONFIG_FIREYEYE_RELAY_WIRED_NC`。NC 选项只用于临时排查，且不具备掉电失效安全。

实体继电器为1/4脚线圈、2脚NO、3脚NC、5脚COM。当前新板已用一根线短接
3/5脚，把 `24V_SW` 引入真正的COM5脚；返修后带载电流已验证。

带载复测时先确认 `fireeye temp` 返回合理温度，避免 NTC 故障触发 ALARM、
继电器释放，导致误判为“继电器不通”或“INA228 无电流”。

被测电源接 U7/JP1，负载接 U8/JP2；两个端子的 2 脚都是板地，不需要额外接
负载回线。还必须单独确认 12V 电池已接入并产生 5V 线圈电源，否则只靠 USB
运行时软件仍可能显示 NORMAL，但继电器不会吸合。

NORMAL 状态下依次测量：

1. 继电器线圈 1 脚对 GND 约 5V；
2. 继电器线圈 4 脚被 Q1 拉低；
3. 继电器 COM 5 脚与 NO 2 脚导通；
4. U8/JP2 的 1 脚 `LOAD_P` 对 2 脚 `GND` 有负载电压。

在约 `1.2V`、`10Ω` 的台架条件下，电源单独接负载曾测得约 `0.118A`。串入载板后
应记录 INA228 的 `I`、`Vbus` 和状态；预期电流量级约 `0.09-0.12A`，实际值受电源
限流和触点压降影响，必须以后续实测为准。

注意：`fireeye current` 在初始化时会释放继电器，只适合检查 INA228 通信和空载
读数。标准 NO 带载测试应运行 `fireeye -v`，让 NORMAL 状态持续励磁并输出周期
数据行。当前版本进入 `fireeye` 或 `fireeye -v` 后只能通过复位开发板返回 `nsh>`。

## 5. 告警闭环

分别模拟过流和过温，确认：

- NORMAL：负载接通。
- WARNING：负载保持接通。
- ALARM：负载断开，声光报警。
- 人工复位后故障仍存在时，系统应重新进入告警，不能永久屏蔽故障。
- 拔掉 INA228、NTC 或破坏 I2C 通信后，连续 3 个采样周期应进入 ALARM 并断开负载。
- 掉电时负载断开。

## 6. 网络

新 W5500 当前已完成 SPI 和 MACRAW 探测，但 PHY 没有 Link：

- `VERR=0x04`，能读取芯片版本寄存器。
- `SN_SR=0x42`，MACRAW socket 已初始化。
- `PHYCFGR=0xB8`，Link 位为 0。
- 同一网线接电脑与树莓派时网口灯正常，接 W5500 与树莓派时两侧不亮。

当前优先怀疑模块 RJ45/PHY/网络变压器链路故障。在获得替换模块或完成进一步测量前，
暂停修改路由和 HTTP 参数，也不要把网络写入“已通过”。PHY Link、固定 MAC 回读、
本机 IP、掩码、路由和 HTTP `POST /api/data` 往返全部通过后，材料才可写
“新载板网络联调通过”。

## 7. 当前下一步

1. 确认 NTC 当前读数稳定在合理范围；异常时检查插接、开路和分压焊点。
2. 保持标准 NO 固件，确认 NORMAL 状态继电器励磁。
3. 完成 INA228 带载电流方向、量级和母线电压记录。
4. 验证 ALARM 断载、掉电断载和 PA0 人工复位。
5. W5500 已完成直连 Ping 和 HTTP 初测；继续验证长时间上报与断线恢复。
