# 火眼使用说明书

本说明书面向火眼电动自行车充电电气安全监测终端的现场操作人员、演示人员和调试人员，说明板端串口、上位机网页、AI 功能以及常见故障的处理方法。操作前应先阅读安全须知，并以实际烧录固件启动时打印的版本为准。

## 一、文档目的与适用范围

本说明书适用于 2026-10 新载板、INA228 电流检测方案、GD32F407VKT6 主控和 MiMo 上位机 AI 研判功能。旧 ACS712 演示板、COM-NC 继电器接法以及“继电器 true 表示断电”的旧语义不属于当前操作范围。

当前设备是 24V 低压充电安全监测原型。硬件已完成的实测包括 INA228 基础带载、NTC 告警闭环、OLED、蜂鸣器、报警灯、继电器基础带载，以及 W5500 直连 Ping 和 HTTP 上报。电流量程、零点、方向、告警断载、掉电断载和长时间网络稳定性仍需继续验收，现场演示不得把这些项目表述为全部通过。

## 二、安全须知

1. 当前板 F1 为 2A 自恢复保险丝，D1 为 40V SS54。禁止在现有板上进行 5A 或 8A 实流测试，也不要把当前 24V 原型表述为可直接用于 48V、60V 或 72V 充电器。
2. 执行 `fireeye test`、`fireeye level` 或带载监测前，应先确认负载、电源和继电器接线安全。`fireeye test` 和 `fireeye level` 会让继电器、蜂鸣器和报警灯动作；不准备观察带载通断时，应断开功率负载。
3. NORMAL 表示软件判断正常，同时会接通负载；WARNING 会保持负载接通并启动声光预警；ALARM 或 SHUTDOWN 会断开负载并持续报警。不要只根据网页颜色判断功率回路一定已经断电，现场维护仍应切断总电源。
4. AI 结果只根据已上报的采样和事件生成，用于辅助研判，不参与跳闸控制，也不能替代计量、消防或电气安全结论。
5. 烧录固件、拆除接线或更换传感器前必须先断电。涉及 24V 功率回路时，应由具备相应电气操作经验的人员完成。

## 三、系统组成与操作流程

| 环节 | 当前实现 | 操作入口 |
|---|---|---|
| 数据采集 | INA228 电流和母线电压，NTC 温度 | 板端自动采样 |
| 本地保护 | 阈值、趋势、连续防抖、状态机 | 板端自动运行 |
| 本地提示 | OLED、蜂鸣器、报警灯、继电器 | 串口命令或告警状态 |
| 网络上报 | W5500 通过 HTTP POST 上报 JSON | 启动 `fireeye` 监测 |
| 网页监控 | 状态卡片、曲线、事件、CSV | `fireeye_monitor.py` |
| AI 研判 | 风险评估、问答、事件报告 | 网页 AI 区域 |

推荐操作顺序如下：

1. 检查电源、负载、继电器、NTC、OLED 和网线连接。
2. 用 115200-8-N-1 参数连接板端串口，确认出现 `nsh>` 提示符。
3. 在 `nsh>` 后输入 `fireeye -v`，启动周期监测和网络上报。
4. 在电脑上启动 `tools/fireeye_monitor.py`，浏览器打开监控页面。
5. 检查网页的电流、温度、母线电压、最后上报时间和事件记录。
6. 演示结束后先断开功率负载，再停止上位机并断开电源。

## 四、板端串口连接

| 参数 | 设置 |
|---|---|
| 控制台接口 | USART0 |
| 引脚 | PB6 / PB7 |
| 波特率 | 115200 |
| 数据位 | 8 |
| 校验位 | 无 |
| 停止位 | 1 |
| 流控 | 无 |

串口终端可使用 PuTTY、MobaXterm、Tera Term 或 `tio`。连接成功后应看到 NuttX NSH 提示符：

```text
nsh>
```

本板当前实测不能同时连接 GD-Link 和串口。需要烧录时连接 GD-Link，需要查看 NSH 或周期数据时切换到串口，完成后再恢复所需连接。该限制属于当前板级连接条件，不是固件通用行为。

## 五、板端串口命令

### 5.1 启动连续监测

```text
nsh> fireeye -v
```

`fireeye -v` 初始化传感器、OLED、网络和状态机，进入无限监测循环，每 10 秒打印一行周期数据，例如：

```text
FireEye: I=0.1300 A, T=25.00 C, Vbus=5.6000 V, raw20=3328, state=NORMAL
```

当前构建没有启用 `CONFIG_TTY_SIGINT`，因此 `Ctrl+C` 不能可靠退出监测循环。需要停止监测时，按开发板复位键或重新上电。不要通过拔掉正在工作的 24V 负载来停止软件。

### 5.2 输出级别

| 命令 | 用途 | 注意事项 |
|---|---|---|
| `fireeye` | 以安静档启动监测 | 只保留告警、错误和启动提示 |
| `fireeye -q` | 显式选择安静档 | 仍会进入监测循环 |
| `fireeye -v` | 启动周期数据输出 | 日常演示和网络联调推荐 |
| `fireeye -vv` | 打开更详细诊断输出 | 日志较多，适合排障 |

本版没有 `fireeye help` 子命令。输入未支持的参数可能进入普通监测循环，因此不要用随意参数尝试帮助。

### 5.3 传感器和执行器自检

| 命令 | 功能 | 执行后的提示 |
|---|---|---|
| `fireeye current` | 打印 INA228 厂商号、器件号、分流/母线原始码、四位小数测量值和校准参数 | 完成后退回 `nsh>`；初始化时会释放继电器 |
| `fireeye temp` | 打印 NTC 原始码、电压和换算温度 | 完成后退回 `nsh>` |
| `fireeye oled` | 执行 OLED 全屏、清屏和 `OLED OK` 自检 | 完成后退回 `nsh>` |
| `fireeye test` | 执行蜂鸣器、继电器、预警音和报警灯联合自检 | 让输出动作；应断开负载后执行 |
| `fireeye level` | 依次让蜂鸣器、继电器和报警灯引脚输出 LOW/HIGH | 直接操作引脚；继电器可能吸合 |

`fireeye current` 的输出格式示例，数值仅用于说明精度：

```text
FireEye INA228: mfg=0x5449 id=0x2281 raw20=2918 bus_raw20=28672 current=0.1140 A bus=5.6000 V gain_ppm=1000000 offset_uA=0
```

`fireeye temp` 的典型输出：

```text
FireEye NTC: raw=2073 volts=1.670 temp=24.45 C
```

INA228 或 I2C 初始化失败时，`fireeye current` 可能返回 `-19` 或 `-5` 一类错误码。`-19` 通常表示没有 I2C 设备节点，`-5` 通常表示地址无 ACK；应先检查供电、SDA/SCL 和接插件，不要反复上电碰运气。

### 5.4 电流精度与校准

2.1.1 起，串口周期数据格式为：

```text
FireEye: I=0.1300 A, T=25.00 C, Vbus=5.6000 V, raw20=3328, state=NORMAL
```

`raw20` 是 INA228 最近一次分流电压原始码，周期行中的 `I` 是滤波后的业务值，
两者用途不同。网页、事件、报告和 CSV 会保留更高精度，但测量准确度仍取决于
增益、零点、分流电阻实际值和参考仪表。

Kconfig 提供两个校准参数：

| 参数 | 默认值 | 说明 |
|---|---:|---|
| `CONFIG_FIREYEYE_CURRENT_CAL_GAIN_PPM` | `1000000` | 百万分之一增益；`1000000` 表示不修正 |
| `CONFIG_FIREYEYE_CURRENT_CAL_OFFSET_UA` | `0` | 零点偏移；`1000` 表示增加 `0.001 A` |

标定顺序应为：先断开负载并记录稳定零点，再使用安全负载和一个经过核对的参考
电流确定增益，最后在第二个安全电流点复核。禁止在当前 2A 保险丝板上直接使用
5A 或 8A 电流标定。默认值保持 `1.0/0`，未完成两点复核前不能宣称电流已校准。

### 5.5 低级诊断命令

以下命令主要供硬件和固件调试人员使用，不属于日常演示流程：

| 命令 | 当前行为 | 使用限制 |
|---|---|---|
| `fireeye adc` | 旧 ACS712 后端的偏置诊断 | 当前 INA228 构建会返回 `-ENOSYS`，不存在可用结果 |
| `fireeye store` | 写一条测试记录并回读 | 当前构建未启用 `CONFIG_FIREYEYE_STORAGE`，不可用 |
| `fireeye -e 20` 或 `fireeye --events 20` | 回放片上 Flash 历史 | 当前构建会提示本地存储已禁用 |
| `fireeye flash` | 直接读取 FMC 并写入诊断字节/字 | 仅限工程师；会修改未使用 Flash，不应在演示现场执行 |
| `i2c bus` | 列出 NuttX I2C 总线 | 只读诊断 |
| `i2c dev -b1 -f100000 0x3c 0x40` | 探测 OLED 和 INA228 地址 | 硬件 I2C 驱动本身仍有已知多字节接收缺陷 |

### 5.6 人工复位和状态含义

主循环运行时，按板载 K2 键会重置状态机到 NORMAL，并关闭声光报警。
2.1.2 起，过流 ALARM 会保持锁存，继电器断开后电流归零不会自动重新接通。
复位前必须先断开或更换异常负载，确认实际电流、温度和接线安全，否则系统会在
连续防抖后再次进入 ALARM。温度告警仍可在降温后自动恢复。

| 状态 | 负载 | 声光输出 | 含义 |
|---|---|---|---|
| NORMAL | 接通 | 关闭 | 参数在正常范围 |
| WARNING | 接通 | 间歇蜂鸣、慢闪 | 电流达到 1.2A、温度或趋势超过预警阈值 |
| ALARM | 断开 | 长鸣、常亮 | 电流达到 1.5A、漏电或关键传感器失效 |
| SHUTDOWN | 断开 | 长鸣、常亮 | 紧急停机状态 |

当前安全构建中，1.2A 电流预警只启动声光提示，继电器仍接通负载；达到 1.5A
进入 ALARM 后才断开继电器。需要预警阶段立即断载时，必须修改状态输出策略，
不能只修改阈值名称。

## 六、启动网页监控台

上位机程序只依赖 Python 标准库。进入项目目录后执行：

```powershell
cd D:\openvela\contest2026_443_fengxieke
python .\tools\fireeye_monitor.py --host 0.0.0.0 --port 8080
```

本机当前 Python 路径也可以使用：

```powershell
& 'D:\PYTHON\Anan\python.exe' .\tools\fireeye_monitor.py --host 192.168.1.100 --port 8080
```

程序启动后终端会打印页面和上报地址，例如：

```text
火眼上位机已启动： http://127.0.0.1:8080
终端上报地址：     http://<本机IP>:8080/api/data
```

浏览器访问：

```text
http://192.168.1.100:8080/
```

如果使用 `--host 0.0.0.0`，应从电脑的局域网地址访问，不要使用另一台设备无法访问的 `127.0.0.1`。Windows 防火墙需要允许 TCP 8080 入站。

### 6.1 常用启动参数

| 参数 | 作用 | 示例 |
|---|---|---|
| `--host` | 指定监听地址，默认 `0.0.0.0` | `--host 192.168.1.100` |
| `--port` | 指定网页端口，默认 `8080` | `--port 8080` |
| `--data-dir` | 修改事件留存目录 | `--data-dir D:\fireeye_data` |
| `--demo` | 启动模拟数据，不接板子也可演示界面 | `--demo` |
| `--no-mimo` | 关闭全部云端 AI 调用 | 只演示数据链路时使用 |
| `--mimo-model` | 覆盖 MiMo 模型名 | 默认 `mimo-v2.6-pro` |

若当前网页没有 AI 结果，先检查启动命令是否包含 `--no-mimo`。该参数会保留 AI 页面区域，但风险评估、问答和 AI 事件研判都会返回“AI 未启用”。

### 6.2 无硬件演示

没有板子时可执行：

```powershell
python .\tools\fireeye_monitor.py --demo
```

模拟数据会周期性进入 NORMAL、WARNING 和 ALARM，用于检查页面、曲线、事件和 AI 功能。演示数据不能用于证明真实传感器、继电器或网络链路通过。

## 七、网页功能与操作

网页每 2 秒刷新一次数据。板端默认每 5 秒上报一次，超过约 15 秒没有新数据时，设备卡片会显示离线秒数。

### 7.1 顶部状态卡片

顶部卡片显示当前状态、电流、温度、母线电压、设备名、最后上报时间和采样率。电流和温度使用滤波后的数据，母线电压使用 INA228 的 VBUS 测量值。网页默认把电流和母线电压显示到三位小数。

### 7.2 实时曲线

曲线显示最近最多 150 个上报点，覆盖时间随实际上报间隔变化。蓝色为电流，橙色为温度，左右轴分别缩放。ALARM 和 SHUTDOWN 区间以红色竖带标记。曲线出现断点或停止更新时，应同时检查串口周期数据和网口连接。

### 7.3 事件记录

状态变化会写入事件表，并默认保存在：

```text
tools\data\fireeye_events.jsonl
```

事件表显示时间、状态、电流、温度、电压和已有 AI 研判。点击右上角“导出事件 CSV”，可用 Excel 打开带 UTF-8 BOM 的记录文件。

### 7.4 AI 实时风险评估

AI 启用后，后台默认每 90 秒评估一次，使用最近约 60 条采样。风险等级分为低、中、高，并显示具体判断依据和处置建议。点击“立即评估”可以手动触发一次。

AI 评估失败不会影响板端采集、报警和网页数据曲线。风险等级不是保护阈值，不能代替 ALARM 状态。

### 7.5 AI 问答

在“AI 问答”输入框中提问，例如：

```text
现在充电安全吗？
刚才为什么报警？
最近温度变化是否正常？
```

每次问题最多 200 个字符，两次提问至少间隔 5 秒。AI 只根据当前状态、近期采样和最近事件回答；数据不足时可能明确说明无法判断。

### 7.6 AI 事件报告

在事件行右侧点击“报告”，网页会生成一份 Markdown 报告，包括事件概要、AI 研判和报警前后采样。同一事件 1 小时内优先使用缓存，报告生成后可预览或下载。

如果 AI 未启用，仍可生成只含事实数据的报告。报告中的 AI 内容是辅助研判，不是事故调查结论。

## 八、启用 MiMo AI

上位机按以下优先级读取密钥：

1. 环境变量 `MIMO_API_KEY`
2. 当前用户目录下的 `.fireeye_mimo.key`

Windows 默认密钥文件路径：

```text
C:\Users\<用户名>\.fireeye_mimo.key
```

也可以在启动前临时设置环境变量：

```powershell
$env:MIMO_API_KEY = '<在此填写自己的密钥>'
python .\tools\fireeye_monitor.py
```

密钥不得写入代码、文档、截图或 Git 提交。默认 MiMo 地址为：

```text
https://token-plan-cn.xiaomimimo.com/v1
```

如果已设置密钥但 AI 仍不可用，检查启动参数是否带 `--no-mimo`、电脑是否能访问 MiMo 服务，以及终端是否输出 AI 请求失败原因。

## 九、网络链路检查

板端当前使用以下直连配置：

| 项目 | 地址或参数 |
|---|---|
| 开发板 | `192.168.1.200/24` |
| 电脑网口 | `192.168.1.100/24` |
| HTTP 服务端口 | `8080` |
| 板端上报路径 | `/api/data` |
| 网卡速率 | 实测 100 Mbps |

推荐检查顺序：

1. 用网线直连电脑网口和 W5500。
2. 确认电脑网口配置为 `192.168.1.100/24`。
3. 在串口执行 `fireeye -v`，确认出现网络初始化日志和周期数据。
4. 在 PowerShell 执行 `ping 192.168.1.200`。
5. 确认 `fireeye_monitor.py` 正在监听 `192.168.1.100:8080`。
6. 检查网页是否显示新的最后上报时间。

Windows 可使用：

```powershell
Test-NetConnection 192.168.1.200
```

短时 Ping 和 HTTP 上报已经验证；5 分钟以上持续上报、断线恢复和跨网段环境仍需继续验收。

## 十、常见故障处理

| 现象 | 优先检查 | 处理 |
|---|---|---|
| 串口无输出 | 线序、USART0、115200-8-N-1、GD-Link 连接 | 切换串口连接，复位后观察启动日志 |
| 找不到 `nsh>` | 固件是否启动、终端流控是否正确 | 关闭流控，重新复位；必要时重新烧录 |
| `fireeye current` 失败 | INA228 供电、I2C、地址 `0x40` | 检查 PB10/PB11、接插件和软 I2C 路径 |
| `fireeye temp` 显示 INVALID | PA6、NTC 分压、接插件 | 检查 NTC 一端到 GND、另一端到 PA6，断路会进入安全侧 |
| `fireeye oled` 返回 `-19` | 没有 `/dev/i2c1` | 检查总线初始化 |
| `fireeye oled` 返回 `-5` | OLED 无 ACK | 检查 `0x3C`、供电、SDA/SCL |
| 监测循环无法退出 | 当前构建未启用 TTY SIGINT | 按复位键或重新上电 |
| 网页打不开 | 进程、监听地址、防火墙 | 启动监控台，确认 TCP 8080 已允许 |
| 网页一直显示离线 | 板端未启动、IP 不同网段、网线或 W5500 | 先 Ping，再看板端网络日志 |
| 网页有数据但 AI 未启用 | 启动参数和密钥 | 去掉 `--no-mimo`，检查 `.fireeye_mimo.key` |
| AI 请求失败 | 网络、模型名、密钥权限 | 查看监控台终端错误并检查服务可达性 |
| `adc` 返回不支持 | 当前为 INA228 后端 | 使用 `fireeye current`，不要继续按 ACS712 流程排查 |
| `store` 或 `-e` 不可用 | 当前构建未启用本地存储 | 使用上位机事件留存；需要 Flash 存证时重新配置并验收固件 |

## 十一、当前验收边界

已经完成并可在说明中如实表述的能力：

- INA228 厂商号、器件号和配置回读。
- INA228 基础带载电流和母线电压随输入变化。
- NTC 常温、超温进入 ALARM、降温恢复 NORMAL。
- OLED 自检和实时监测显示。
