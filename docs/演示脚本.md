# 火眼·作品演示脚本（录屏 ≤5 分钟）

> 演示素材就是 PC 端算法原型 `app/fireeye_prototype/algorithm_prototype.py`，它完整演示了火眼的"采集→滤波→阈值/趋势→状态机报警"核心逻辑，和烧进固件的 C 代码同源。按下面流程录屏即可。

## 0. 准备工作

在电脑上安装依赖并进入仓库：

```bash
pip install numpy matplotlib
cd contest2026_443_fengxieke/app/fireeye_prototype
python algorithm_prototype.py
```

会生成 `fireeye_algorithm_results.png`（电流/温度曲线 + 状态着色）。

## 1. 录屏流程（约 3~4 分钟）

### 开场（30s）- 作品是什么
- 一句介绍：火眼 = 电动自行车充电电气安全监测终端，基于 openvela + GD32F407。
- 说明痛点：电动自行车入户充电火灾；电流异常、温升是热失控最直接前兆。
- 展示代码结构：`app/fireeye/`（滤波/阈值/状态机）+ `app/fireeye_prototype/`（PC 算法验证）。

### 运行算法演示（1~2 分钟）
- 运行 `algorithm_prototype.py`，窗口/终端依次打出：电流原始/滤波范围、**预警/报警次数**、温度**预警/报警次数**、漏电事件数、状态机各状态采样数。
- 强调结果：模拟的"过流 + 超温"段被正确判为 **ALARM（报警）**，系统进入报警态——这就是核心判定逻辑。
- 展示图表：电流、温度曲线 + 报警区间着色。注意本次模拟数据是 NORMAL 直接跳到 ALARM（预警次数为 0），
  录屏时按实际输出讲，不要说成"NORMAL→WARNING→ALARM"；想演示 WARNING 段需要先把模拟数据的爬升段调慢。

### 展示代码与适配（1 分钟）
- 简述：`app/fireeye/src/` 各模块（filter/threshold/fsm/main）；
- 要点：**新硬件适配**——把 openvela 移植到官方未支持的 GD32F407（补充 chip/pinmap/memorymap/progmem 分发、25MHz/168MHz 时钟、编译+烧录成功、固件含 fireeye），见 `docs/adaptation_F407.md`。

### 收尾（30s）
- 说明端侧离线闭环、电气侧防控的价值；
- 未来工作：真机传感器接入（ADC/GPIO/OLED）、网络上报（W5500/MQTT）、存证（littlefs）。

## 2. 录屏建议
- 用 OBS / 系统录屏，1920x1080；
- 终端 + 图表窗口并排；
- 旁白口头说明（或录制后加字幕），符合≤5 分钟。

> 提示：脚本末尾会 `plt.show()` 弹出图表窗口并一直等待，关掉窗口进程才结束；
> 纯命令行/远程环境请先 `set MPLBACKEND=Agg`（Linux：`MPLBACKEND=Agg`），否则会一直挂着。

## 3. 演示要点（评委会关注）
- 算法**是真的**：实现了滤波（滑动平均+低通）、阈值+趋势、连续 N 点防抖、四态状态机；
- 结果**可复现**：跑原型即出 57 次报警，和模拟的过流/超温段对应；
- 适配**有成果**：openvela 在 F407 上编译+烧录+应用编入（见适配文档）。
