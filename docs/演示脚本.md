# 火眼·演示视频脚本（真机版，≤5 分钟）

> 版本：2026-09-13 真机实测版 ｜ 适用固件：`fireeye_p1_168MHz_20260911.hex`
> 拍摄对象：GD32F407VKT6 开发板 + ACS712 电流模块 + NTC 温度探头 + 报警灯模块 + 蜂鸣器 + 继电器 + 12V 风扇负载
>
> 本脚本替代旧的 PC 端 Python 原型脚本（`app/fireeye_prototype/`），录制时以真机为主线，
> PC 原型可作为"算法先行验证"的补充素材出现在画中画里。

---

## 一、录制前准备

### 1.1 硬件与道具

| 类别 | 物品 | 用途 |
|---|---|---|
| 主系统 | 开发板 + USB-TTL + 全部模块接好 | 主角 |
| 负载 | 12V 风扇（串在 ACS712 与继电器 COM-NC 上）+ 12V 电源 | 演示"监测同回路 + 报警断电" |
| 温度源 | 保温杯 2 个：50℃、65℃ 热水 + 温度计 | 触发预警 / 报警 |
| 过流模拟 | 两个 10kΩ 电阻（分压 3V3 → 1.65V ≈ 12A） | 触发过流报警 |
| 调试终端 | 电脑 + 串口助手（115200-8-N-1，字号调大） | 展示实时数据 |
| 固定与补光 | 纸板/亚克力底板、扎带、手机支架、台灯 | 防止线松、画面稳定 |

### 1.2 录制前自检（不录，但必须做）

```bash
nsh> fireeye test     # 蜂鸣器 3 短声 → 继电器吸合 2s → 预警音型 → 报警灯亮灭 ×3
nsh> fireeye level    # 三个输出脚 LOW/HIGH 各 2 秒，确认模块极性（本项目：继电器/蜂鸣器低电平触发、报警灯高电平触发）
nsh> fireeye          # 正常态：风扇转、灯灭、蜂鸣器静音、state=NORMAL
```

确认正常态后**再开录**。若某一步不对，先按 `docs/开发板接线.md` 排错。

### 1.3 拍摄设置

- 手机/相机：横向 1080p 30fps，固定机位，别手持
- 光线：侧上方台灯补光，避免 OLED 与串口屏幕反光
- 声音：环境安静；旁白可后期配（推荐），也可现场讲
- 素材：关键镜头（报警瞬间、风扇由转→停）单独多录 3 遍备用

## 三、旁白逐字稿（可直接照念）

### 【0:00–0:20 开场】

「大家好，我们的作品叫**火眼**，是一台面向电动自行车充电场景的**电气安全监测终端**。
它监测充电回路的**电流和温度**，一旦异常，就地声光报警，并且**自动切断充电回路**——
从电气侧阻断充电火灾。」

### 【0:20–0:50 系统构成】

「这是系统的全貌。核心是一块 **GD32F407** 开发板，跑的是 openvela 操作系统。
电流由这只 **ACS712 霍尔电流传感器**采集，它直接串在充电回路上；
温度由贴在被测点的 **NTC** 采集；报警由蜂鸣器和这只报警灯完成；
而这一路 **12V 风扇模拟的是充电负载**，它的供电必须经过继电器的常闭触点。」

### 【0:50–1:30 正常状态】

「现在系统正常运行：风扇转，说明继电器没有动作、负载正常供电；
OLED 上显示当前状态、电流和温度；串口每 10 秒打印一次数据。
整个采集、判断、报警都在**端侧离线完成**，不依赖网络，断网也不影响安全保护。」

### 【1:30–2:40 过温报警与联动断电】

「我们把 NTC 放进 50 度的温水里。可以看到温度上升到 45 度以上后，
系统进入**预警**状态：蜂鸣器间歇报警、报警灯慢闪，但**风扇继续转**——
预警只是提醒，不切断供电。」

「现在换成 65 度的水。温度超过 60 度的报警阈值，系统进入**报警**状态：
蜂鸣器长鸣、报警灯常亮，同时**继电器动作，风扇立刻停转**——
这就是从电气侧阻断事故的关键一步。」

### 【2:40–3:30 过流报警】

「现在演示过流保护。现场没有真实的大电流负载，
我们用**等效电压注入**的方式模拟传感器输出，来代替大电流工况。」

（拔掉 ACS712 输出，接入 10k+10k 分压）

「可以看到电流读数迅速上升，超过预警阈值后先预警，继续升高超过报警阈值后进入报警，
风扇同样被切断。」

### 【3:30–4:00 人工复位】

「故障排除后，按下板载按键即可人工复位：报警停止、继电器释放、负载恢复供电，
系统回到正常监测状态。」

### 【4:00–4:30 新硬件适配（亮点）】

「这个作品的另一个亮点是**新硬件适配**。大赛提供的板卡实际芯片是 **GD32F407VKT6**，
而 openvela 官方对这颗芯片的支持并不完整——缺少芯片分发的头文件映射、内存映射和 Flash 扇区定义。
我们补齐了这些适配，修正了 25MHz 晶振下的时钟配置错误，并且**自行实现了 GD32F4 的 ADC 驱动**，
因为官方代码里并没有 ADC 驱动和寄存器定义。现在 openvela 已经在 F407 上稳定运行。」

### 【4:30–4:50 收尾】

「火眼把『监测—判断—声光报警—自动断电』做成一个端侧闭环，
成本低、可复制，适合部署在小区充电区和楼道充电点。
后续我们计划加入**联网上报**和**本地存证**，让每一次报警都有据可查。」

## 四、拍摄与剪辑要点

1. **先录关键 5 秒**：报警瞬间（灯亮 + 蜂鸣器 + 风扇停）单独录 3 遍，剪辑时插进去最稳
2. **数值要看得清**：串口字号调大，OLED 尽量正对镜头；看不清就用画中画放大
3. **加字幕**：旁白听不清也能看懂，尤其"45℃ 预警 / 60℃ 报警 / 5A / 8A"这些数字
4. **背景音乐**：用无版权素材，音量压到 -20dB 以下，别盖过解说
5. **诚实口径**：过流段必须说明是"等效电压注入模拟"，不要含糊；温度段是真实触发可以强调
6. **导出**：mp4 / 1080p / 时长 4:30 左右（要求 ≤5 分钟，别卡线）

## 五、常见问题

| 现象 | 处理 |
|---|---|
| 泡水后温度上不去 | 水温不够；50℃ 预期 3~5 秒内进入预警（滤波及 NTC 热惯性有滞后）|
| 预警→报警跳太快，录不到预警 | 用 55℃ 左右的水停在预警区多拍几秒 |
| 报警时风扇没停 | 检查继电器是否接在 COM-NC（不是 NO）|
| 读数是负数 | ACS712 的 In+/In− 接反，两根线对调 |
| 串口乱码 | 波特率 115200、8-N-1；固件日志为英文，工具按 UTF-8 或 ASCII 显示 |
| 电脑与板子抢串口 | 录屏用串口助手时，关闭其他占用串口的程序 |
